# Website and report-page rules (website/buyer-voice-website/)

Directory-scoped instructions for the single Astro project serving buyervoice.ai. Brand identity, git, and repo-wide conventions live in the root `CLAUDE.md`; research methodology (statistics, tiers, percentage rules) lives in `research-projects/CLAUDE.md` and binds every report page built here.

## Internal vs public zones

- **Public pages** live in `src/pages/` (top level), visible at `buyervoice.ai`.
- **Internal pages** live in `src/pages/internal/`, gated by Cloudflare Access (Google OAuth) at the CDN edge; no auth code in Astro.
- Internal pages use `InternalLayout.astro` (no analytics, `noindex`, sidebar nav). The dashboard at `/internal/` lists everything. `robots.txt` blocks `/internal/`.

## The reports manifest is the single source of truth

`src/data/reports.json` drives the dashboard's Reports section, the internal sidebar's Reports category, the worker's `GATED_REPORTS` / `DEFAULT_PUBLIC_REPORTS` blocks (regenerated by `scripts/gen-report-registry.mjs`, which runs automatically before every build), and the precheck's registry-consistency checks. **Add or change a report by editing that one file, never the dashboard, sidebar, or worker directly.** Fields per row: `slug`, `name`, `sidebarName`, `desc`, `href`, `internal` (null keeps it out of the sidebar), `publicSlug` + `publicPath` (enables the KV visibility toggle), `defaultPublic` (Maze partner editions only), `dataFolder`, `precheckSkip` (legacy exemptions only; never on new reports).

The worker fails CLOSED: when the `REPORT_VISIBILITY` KV binding is absent (preview deployments), only `defaultPublic` rows serve; everything else 404s. After a new report deploys, Forest flips the KV toggle on the dashboard once to make it public.

## Building a research report

**Open `src/pages/hr-report/index.astro` FIRST as the visual + flow reference (mandatory).** It is the canonical BuyerVoice report design: section flow AND visual vocabulary.

**Canonical section flow (mirror exactly unless there is a specific, stated reason):** 1 Executive Summary (4-card stat grid + 5-7 callouts + recommendation table + report-navigation table), 2 Customer Insights/Findings, 3 Competitive Position, 4 Brand & Marketing Recommendations, 5 Product & Digital Recommendations, 6 Sales/Retail & Growth Recommendations, 7 Retention & Risk, 8 **Methodology LAST** (four subsections: Sample design; Statistical methodology; Coding and reliability; Known gaps). No Consumer Language Bank section; a language-bank pointer belongs inside Methodology.

**Both pages in the same pass (mandatory):**
1. Report content as a shared body at `src/components/<slug>/ReportBody.astro`.
2. Internal page at `src/pages/internal/<slug>/index.astro` (`includeAnalytics={false}`, `noindex={true}`).
3. Public page at `src/pages/<slug>/index.astro` (`includeAnalytics={true}` is non-negotiable for public pages).
4. Add the row to `src/data/reports.json` (this replaces the old hand-edits to the dashboard, worker, and sidebar) and run `npm run gen:registry`.

**Data binding.** Every number in the body binds to `report-stats.json`, produced by the generic stats builder (`research-projects/6 Analyzing and building a report/shared/build_report_stats.py` + a per-study `report-spec.json`). Copy the study's `report-stats.json` (and `verbatim-exemplars.json` for drilldowns) into `src/data/<slug>/`. Hand-typed percentages are a precheck warning and the documented route to stale prose.

**Shared components (use for every NEW report; legacy inline CSS stays as-is):** import from `src/components/report/`:
- `ReportLayout.astro` (cover, accordion wiring, auto-numbering, PDF button, palette, GA injection), `Section.astro` (always collapsed; never pass `open`).
- `Chart.astro` — canonical theme bar chart: full-width gray track, fill at RAW prevalence percent (never scaled to the max), percentage-only label inside the bar's right edge, single fill color per chart (`color` prop: signal for frustrations, teal for positives, warm for triggers, ink for neutral), dashed overall-average line, sig superscripts, `drilldownId` for click-to-quotes.
- `PairedChart.astro` — paired bars with fixed-width labels (never `min-width`), asterisked pp delta, `noDelta` variant.
- `Scatter2x2.astro` — frequency × BWS intensity scatter with median quadrant lines; the source note must carry the grouping's BWS alpha.
- `StatGrid.astro` (cover + `compact` cohort-descriptive variant), `Callout.astro` (insight / opportunity / vulnerability / neutral; one finding per callout), `CrossTab.astro` (`percentDirection` prop governs highlighting), `DrilldownModal.astro` (one instance per report + `verbatim-exemplars.json`; every theme bar chart must be drillable; BWS chips with legacy 1/2/3 tolerance).

**Cover rules:** logo as HTML text (28px Fraunces 600, `.AI` in signal red), block-level `<a href="/">` with `width: fit-content`; title in `var(--signal)`; 4-card stat grid full-width (no max-width); no border/margin under the cover (64px padding only); `hideClientOnCover={true}` for illustrative clients; clean prose scope subtitle (wave parentheticals belong in Methodology). "Save as PDF" exactly, top-right, signal red.

**Accordions:** two-digit numbers, Fraunces 32px/600 signal number glyph, 22px/600 title, `+` icon in signal, border-bottom on every accordion, ALL collapsed on load, no exceptions.

**Cross-wave comparisons** use the demographically matched cohort (retiree over-samples excluded), with the matched n in the source note. Cohort-descriptive `compact` stat blocks open sections that speak for one cohort.

## Pre-publish: run `npm run precheck` (mandatory, non-skippable)

After `npm run build` and BEFORE any deploy, run `npm run precheck`. It mechanizes the pre-publish checks against the built HTML plus registry consistency: em dashes, decimal percentages, open accordions, reader-visible Q-numbers, mojibake, bar-value parentheticals, p-values in prose (source notes and chart footnotes are exempt by design), page pairs, analytics props, paired-label `min-width`, hand-typed percentages, `__VX` payload size and PII, and worker/manifest agreement. Fix every ERROR at the source; `precheckSkip` exemptions are frozen legacy only. `npm run deploy` chains build + precheck + wrangler.

**Six checks stay manual (browser pass before deploy):** horizontal scroll bars at 1280px; overlapping text; clipped labels; PDF print expansion; the same data presented twice; process-language in body prose. Also confirm abbreviations are spelled out on first use and cross-references resolve.

**Q-numbers:** never anywhere a reader sees, INCLUDING source notes. Source notes spell out the verbatim question text. Q-ids live only in analyst files (A6/B6).

**P-values:** never in body prose or exec-summary callouts; test detail belongs in the source note under the chart (tier language + alpha footnote carry the claim).

Every report uses the BuyerVoice.AI brand system by default, regardless of the client. **Partner co-branded editions are opt-in only** (build only when Forest asks by name, always in addition to the canonical page, at `/<partner-slug>/<report-slug>/`). ## Brand system (mandatory on every page)

Palette (CSS variables in `src/layouts/Base.astro` / `InternalLayout.astro`): `--ink: #0B1F3A`, `--paper: #F7F5EF`, `--signal: #B8341B` (max one accent per screen), `--rule: #1A1A1A`, `--muted: #6B6B6B`, `--border: rgba(11,31,58,0.10)`, `--card-bg: rgba(11,31,58,0.03)`. Typography: Fraunces headlines, DM Sans body; never Playfair Display or Inter. Favicon `/favicon.svg` + `theme-color #F7F5EF` on every page (standalone pages add it explicitly). For large cover logos render HTML text, not the positioned SVG (Fraunces glyph widths open a gap); `/images/logo-nav.svg` is fine at sidebar scale. **No KwantumLabs text anywhere on the site** except the `/internal/four-products-v1/` subtree; methodology attribution says "BuyerVoice.AI". That subtree is the former KwantumLabs website, kept as a historical artifact (Forest, September 28, 2026): do not remove, update, or restyle it, and never use it (or `src/components/four-products/`, `src/layouts/FourProducts*.astro`, `src/styles/four-products-global.css`) as a reference for brand, copy, or design. The dashboard and the sidebar label it "Historical artifact".

## The privacy policy (`/privacy`)

`src/pages/privacy.astro`, published September 28, 2026 and linked from the homepage footer. Forest's choices: the company is BuyerVoice LLC, deletion requests are answered within 45 days, and no service provider is named. Google Analytics is the one exception, because Google's terms require a site that uses it to say so and to link to how Google uses the data. Its two sentences on deletion and rewards are word for word the last paragraph of the interview platform's default consent text (`AI-moderator-product/platform/api/src/studies.ts`, `DEFAULT_CONSENT_EN`): change one, change the other. Change the "Last updated" date with any change to the wording. The record of the wording and the choices is `outputs/content/website/privacy-policy.md`.

## Non-report internal pages

Create `src/pages/internal/{page}/index.astro` with `InternalLayout`, then add it to the dashboard page's non-report sections and the sidebar's static entries in `InternalLayout.astro` (only REPORTS come from the manifest).

## Deployment

```
cd website/buyer-voice-website
npm run build
npm run precheck
npx wrangler pages deploy dist --project-name buyervoice-ai --branch main
```

`--branch main`, never `master` (master deploys to preview). `npm run deploy` runs all three. Deploy only when Forest asks.

## Data-dependent pages

Some internal report pages load research data via `readFileSync` at build time and render a "data not available" placeholder when the files are absent; the public hr-report pages are underscore-disabled for the same reason (the precheck warns rather than errors on their missing dist pages).
